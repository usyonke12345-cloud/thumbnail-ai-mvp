# Day4 — 失敗からの復旧と参考サムネの分析準備

作業ブランチ: feature/day4-recovery。開始時main: e54b908。

## 実装・確認

- 再生成に失敗しても前回の候補と保存操作を残す。成功したときだけ表示を置き換える。
- 送信中の重複submitを止める。外部APIの同時1件制限も維持。
- 画面の待機は190秒まで。サーバーの外部API期限は既定120秒、設定可能な最大180秒。
- 接続失敗、生成失敗、期限超過のあとボタンを戻す。自動再試行はしない。課金済みの可能性がある失敗は利用履歴確認を案内。
- 回数上限の既定値と.env.exampleを1回/起動へ変更。すでにOPENAI_MAX_CALLSを指定した設定はその値を使う。ユーザーの.envは変更しない。
- 実ブラウザで、無料候補生成→確認用サーバー停止→失敗しても3案維持→サーバー復旧→再試行成功を確認。
- 人工応答のテストで、期限超過・接続失敗・APIエラー後の復旧と重複送信防止を確認。有料API呼び出しなし。

## 費用を限定する設定

1リクエストで背景1枚だけ（n=1、low、1536×1024）、候補3案・PNG/JPEG保存はその背景を再利用する。
OPENAI_MAX_CALLS=1、OPENAI_TIMEOUT_MS=120000を検証用の推奨設定とする。失敗も回数に含む。
これは回数制限であり、ドル金額の上限ではない。サーバー再起動・別プロセスで回数はリセットされる。期限超過でもプロバイダー側の生成や請求を取り消せるとは限らない。再起動して有料生成を増やす前に利用履歴と残高を確認する。
現段階では1回の正確な最大請求額を保証していない。この制限と、料金・残高の確認をセットで運用する。自動チャージ設定やAPIキーは今回変更しない。
