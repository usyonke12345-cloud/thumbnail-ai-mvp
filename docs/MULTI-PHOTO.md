# 複数の写真から完成PNGを作る

2026-10-31。メイン写真1枚と追加写真2枚、合計3枚まで。同じサムネイルに使いたい人物・料理・風景を渡し、AIが文字と素材の配置を考えます。写真を選ぶだけでは外部送信や課金はありません。

## 操作

1. `/editor` の「使う写真」にメイン写真を読み込む。「1枚の写真を全面に使う」の状態で使います。
2. 「追加の写真」で最大2枚を選ぶ。不要な写真は「この写真を外す」で取り除く。
3. 動画タイトルを入れ、見出し・構図は必要に応じてAIに任せる。仕上がりのイメージは任意。
4. 送信する全写真を確認し、有料送信の確認欄をチェックして生成する。既存の生成枠が必要です。

追加写真はPNG・JPEG・WebP、元ファイル20MiB・4000万画素以内。全体を1280×720の透明な枠内に収め、縦長の写真も切り落としません。メイン写真は従来の切り取り操作が適用されます。どの入力も送信するPNG data URLは3MiB以内。1280×720・上限内のPNGは追加写真も元のバイト列を使います。同じPNGの重複は生成前に拒否します。

無料編集キャンバスはメイン写真のプレビューです。追加写真との合成は生成時に行います。入力中・生成中の写真切り替えを保護し、送信する写真と入力はクリック時点で固定します。

## 生成と人物の扱い

写真は事前に1枚のコラージュへまとめず、メイン、追加1、追加2の順に別々の`image[]`として同じ画像編集へ送ります。その後に修正元、送信許可済みの参考画像を置き、指示内の画像番号も合わせます。

モデルは既存の`gpt-image-2.5-flare`、medium、1536×864、1枚出力。1回の有料編集で、自動再試行はありません。[Images editの公式API](https://developers.openai.com/api/reference/resources/images/methods/edit)にある複数画像の入力方式を使います。[モデルの公式仕様](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)も参照。

素材は入力写真に実際に写っているものだけを使い、写真にいない人物を足さないよう指示します。同じ人が複数写真に写る場合は1人として扱い、別々の顔や身体を混ぜません。追加写真それぞれから役立つ素材を使い、背景・物体の形や視点を保つよう指示します。人物検出・同一人物照合・画素が同一の切り抜きは実装していません。人物追加、描き直し、写真の不使用がないか、完成画像で確認する必要があります。

複数写真は`ai-complete-0.11.0`。写真1枚は既存の`ai-complete-0.10.2`と生成指示を維持します。実画像での複数写真の品質検証は未実施です。

## 記録・移行

比較一覧には全入力写真を表示します。写真の内容と順序のハッシュで組を決めるため、追加・削除・入れ替えは別の比較組になります。

- JSON・共有ZIPに正規化した全入力PNGと完成PNGを含め、読込時に順序・SHA-256を再照合します。共有ZIPでは同じ画像を1回だけ保存します。
- 下書きには追加写真の元ファイルと送信PNGを両方保存します。下書きZIPで入力欄・メインの切り取り・写真を別PCへ移せます。有料送信の確認は移しません。
- 「この画像を修正」では、その画像の生成時に使った全入力写真を復元します。別案件で今選んでいる写真へ置き換えません。
- 下書きZIPは複数写真のみ`photo-editor-backup-1.1.0`。古い1.0.0は引き続き読み込めます。旧アプリが新ZIPの追加写真を黙って落とすことを防ぎます。
- 全体60枚・案件24枚・組12枚、重複を除いた192MiBの履歴上限、JSON/ZIPの70MiB上限は維持します。追加写真も容量へ数えます。

## 共有契約への影響と限界

OpenAPIは0.3.9。人工fixtureは`docs/fixtures/multi-photo.json`。shared・server・解析の変更は採点担当との相互レビュー対象です。Candidate、Assessment、採点値・重み、pipeline、依存パッケージは変更しません。

| 対象 | 複数写真の追加 | 1枚写真 |
| --- | --- | --- |
| 完成生成入力 | 任意の`additionalImageDataUrls`、最大2枚 | 省略・空配列は従来経路 |
| 完成生成応答 | `sourcePhotoSha256s`、メインを含む2〜3件を順序付きで返す | 追加しない |
| 比較JSON | 1.11.0、groupの追加URLとinputの`additionalSourceSha256s` | 既存形式を維持 |
| 画像診断入力 | image-assets-1.1.0、`additionalSourcePhotoAssetIds` | 1.0.0 |
| 画像診断応答 | complete-png-diagnostics-0.1.2、追加写真の参照 | 0.1.1 |
| 解析dataset | 1.10.0、全写真資産を保持、base64は含めない | 既存形式を維持 |
| A入力固定 | case 1.1.0、`additionalSources`、全写真の順序とハッシュ | case 1.0.0 |

生成のJSON本文上限は32MiB、入力固定は10MiBへ拡張。画像診断は合計4資産・32MiBを維持し、3枚の入力写真がある場合は完成PNGを1枚ずつ診断します。資産はハッシュごとに1回だけ展開し、画素をdatasetへ残しません。全入力写真が読めなければ比較完了へ数えません。診断は輝度等に限り、完成PNGの品質点数はnullです。

人物範囲の記録は1枚写真向けなので複数写真では無効にします。Bの盲検資料も、採点側のシートが全入力写真へ対応するまでは複数写真を`multi_photo_review_not_supported`として除外します。

A固定ZIPには`source.png`、`source-2.png`、必要なら`source-3.png`と短い依頼文を保存します。複数写真は`reference_multi_photo`と明記し、PR #11の正式な1枚写真のA比較には混ぜません。既存A用5組の写真・出力・評価記録は変更しません。

自動テストは人工PNG・モックAPIで、別画像としての送信、指示の素材範囲、制限、入力の改変、保存・復元・修正・診断を確認します。実際の有料画像生成と人の評価の代わりにはなりません。
