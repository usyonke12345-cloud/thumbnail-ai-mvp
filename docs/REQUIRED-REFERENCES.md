# イメージを共有し、100実例を参考に作る

2026-10-31。エディターの通常生成では「仕上がりのイメージ」を必須にし、条件確認済み・観察済みの100件の実例を参考候補にします。写真・動画タイトルと、希望する雰囲気を用意してください。例を選ぶだけでも入力できます。

## 何を生成へ使うか

最近6か月の公開、100万再生超、4分以上、ライブと配信アーカイブを除外、同一チャンネル最大5件という既存の収集条件を維持します。公開日・再生数はYouTube Data APIで確かめます。実画像を見た字体・配置・素材の使い方の観察があり、画像ハッシュが一致するものだけを数えます。

100件全体に対して、入力した雰囲気との一致を優先し、動画の内容と素材の使い方も使って最大5件を選びます。穏やかな雰囲気の指定には、題材が一致するだけの強い装飾より、落ち着いた字体・構成の観察を優先します。複数写真では写真を組み合わせた例も優先候補です。同じチャンネル・同じ画像ばかりにならないようにします。

生成に送るのは、選んだ例の汎用的な字体・構成・使う条件・避ける条件です。元の実例画像は送信許可の根拠が記録されている場合だけ添付します。現在の実台帳100件は画像送信の許可が0件なので、観察記録だけを送ります。実例の人物、商品、ロゴ、文言を素材として持ち込む指示ではありません。

[OpenAIの画像プロンプトの公式ガイド](https://developers.openai.com/api/docs/guides/image-prompting)に従い、希望するスタイル、素材、変更する範囲を分けて指示します。モデルは既存のgpt-image-2.5-flare、medium、1536×864、出力1枚、自動再試行なし。追加の文章APIや学習処理は呼びません。

候補を絞る処理は文章のタグによる選定で、元写真の理解をコードで行った結果ではありません。最終的な字体・構成は同じ1回の画像編集でAIが判断します。100枚の画像を毎回そのまま送る方式でも、モデルの重みを学習させる方式でもありません。実際に採用された字体や品質向上は、完成画像で確かめる必要があります。

## 生成前に止める条件

- イメージが空欄なら入力欄へ案内し、有料要求を出しません。空白だけの指定も受け付けません。
- 条件確認と目視観察のそろった実例が100件に満たない場合は、生成プロバイダーを呼びません。実例なしや少数の例へ黙って切り替えません。
- 固定したA入力からイメージや参考の台帳が変わった場合は、従来どおり生成前に止めます。通常生成へ戻すときは「固定を解除」を使います。

期限切れのメタデータや画像は既存の30日ルールで除外します。ライブラリを更新し、新しい画像は目視観察を追加してください。収集・参考候補の確認は画像生成を呼びません。

今回、台帳を更新して新しく入った10件を実際に目視し、100件をそろえました。再生数は収集の条件であり、サムネイルの品質やCTRへの効果の証明ではありません。

## 契約と旧記録

OpenAPI0.3.10、生成0.12.0。通常のエディターは`referenceMode: required`を送ります。このモードでは、生成・無料入力固定・無料参考プレビューに空欄でない`visualIntent`が必要です。旧APIの省略・off・auto、以前の入力固定、保存画像の読込は互換性を維持します。旧下書きを通常編集へ戻す際は新しい必須方式へ移しますが、保存された完成画像・評価は書き換えません。

参考記録`thumbnail-reference-context-1.1.0`に、考慮した100件の`poolSize`と`poolSha256`、正規化したイメージの`visualIntentSha256`を追加します。選定方式は`visual_intent_then_content_tags_then_image_model`。選んだ候補と画像の送信有無も残します。これらは入力の監査情報で、画像の改善を検証した印ではありません。

新しい参考記録は比較JSON、共有ZIP、下書き、解析、A入力固定と照合結果へ保持します。比較・datasetの外側の版は維持し、入れ子の参考記録の版で区別します。旧アプリは未知の参考記録を黙って落とさず、対応外として拒否します。過去のA用5組の画像と返送ZIPは更新しません。

Candidate/Assessment、採点値・重み、pipeline、採点担当のdata/scoring、依存パッケージは変更しません。shared、server、生成契約と解析互換性は相互レビュー対象です。人工fixtureは`docs/fixtures/required-reference-intent.json`。

テストは空欄と実例不足で有料処理へ進まないこと、100件全体の照合、イメージによる候補の違い、1回の画像編集、素材の権限、JSON/ZIP/下書き/解析と入力固定の保持を確かめます。追加の有料生成による新方式の実画像検証は未実施です。
