# 実例から字体・構成のストックを増やす

2026-10-19。現在の課題は「使える画像は出たが、写真が変わっても大きな横見出し・似た字体・白と黄色へ寄りやすい」こと。最初の収集目標は旅・日常・体験系の実例30件。件数を満たすことより、異なる構造と適用条件を把握することを優先する。

## ストックと追加学習の違い

使用中の `gpt-image-2.5-flare` は、[OpenAI公式のモデル情報](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)でfine-tuning非対応とされている。URLや画像を保存してもモデルの重みは変わらない。

この作業で増やすのは、実例の観察記録と、そこから抽象化した生成用の条件である。モデルへ渡す前に「維持する写真の要素」と「借りる文字・配置の関係」を分ける。[公式の画像プロンプトガイド](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)のstyle transferでも、維持する視覚的な特徴と変更する内容の明示を勧めている。

## 1件に残す情報

- 出典URL・動画ID・確認日・確認方法。検索で見つかっただけなら `candidate` とし、目視分析済みにはしない。
- 写真／イラスト／複数素材の別、実際の主役の位置、顔・手・重要な物の占有領域。
- 見出しの意味：話題名、発見、体験、対比、問題など。実例の言葉を別動画へコピーせず、短くする関係を記録する。
- 字体の見た目：ゴシック／明朝／手書きなど、太さ、縦横の比、傾き、字間、行間。フォント名や数値は確認・測定できた場合だけ記録する。
- 見出しの位置、主な行数、揃え方、写真に対する文字の割合、前置きと中心句の強弱。
- 文字色、強調色の用途、縁取り、影、文字背面。影の不透明度など未測定の数値は `null` のままにする。
- 好みの理由は本人が述べた範囲だけ。アシスタントの観察と混ぜない。
- 使える写真の条件と、使わない条件。比較写真や図表を必要とする構成を、写真1枚の編集へそのまま当てはめない。
- 画像の保存・API送信の許諾状況。URLと観察の記録を、原画像の利用許諾として扱わない。

記入済みの台帳・実画像・本人の評価は `data/private/reference-library/` に置く。既存の `/references` はURLと文章メモを保存する画面であり、登録だけで生成へ反映する機能はまだない。

## 段階と件数

`candidate`（URLだけ）→ `observed`（実画像を確認）→ `draft_pattern`（再利用する関係を整理）→ `generation_checked`（別素材の完成画像を本人が確認）と進める。過去の観察の移行は `prior_observation` とし、現在のサムネを再確認したことにはしない。

同じ動画IDはURLが違っても1件。同じチャンネルの似た作風だけで30件を埋めず、可能なら10チャンネル程度へ分散する。再生数を品質の正解やCTRの証拠にしない。本人が好みと答えていない例を、好みの正例として扱わない。

まず、下部の横見出し・上部の誌面型・片側の短い見出し・主役を挟む文字・写真を広く見せる小さめの見出しなど、観察された配置の違いを探す。この分類名は収集の目安で、実例の件数や品質の認定ではない。字体・強調色・行数も併記し、位置だけ違う同一ポスターへ集約しない。

30件を確認した後、重複をまとめて8〜12程度の型を候補にする。使える型の数は実例次第で、先に数を埋めない。各型には出典ID、適用条件、避ける条件、観察の確かさを付ける。

## 生成への接続

写真・内容・希望の雰囲気から適合する少数の型を候補にし、同じ画像編集の呼び出し内で実際の空間に合わせて選ばせる。利用者に型や見出しの選択を必須にしない。単純な順番切り替えや、人物を動かして違いを作る処理は入れない。

収集した候補をそのままプロンプトへ全件追加しない。観察が具体化し、適用条件をレビューしてから、生成版・A固定のコードハッシュ・テストを同じ変更で更新する。生成の指示に渡す型のIDと版は、将来の追跡対象とする。モデルが実際にどの型を選んだかは、取得していなければ未確認とする。

同じ写真・タイトル・補足・イメージで現行版と比べ、使えるか、見どころが伝わるか、字体が内容に合うか、写真が自然かを記録する。続いて未使用の写真でも確認する。A/Bのholdout記録を好みの調整に使わない。既存の生成結果・不採用記録は上書きしない。

## 今回の到達点

収集・観察・型の検証を分ける台帳を非公開フォルダに作成した。既存5例は過去の観察から移行し、新しく検索で見つけた4例は実画像未確認の候補として登録した。その後、ブラウザの公開検索結果で旅系を中心に新たに30件（25チャンネル）を目視確認した。30件のうち写真1場面は15件、複数写真は15件。既存5例のうち1例も再確認した。

現在の台帳は `data/private/reference-library/2026-10-19/observed-catalog.json`、10種類の型の案は `pattern-drafts.json`、読むための一覧は `index.html`。初期の `catalog.json` は作業開始時点の記録として残す。10案のうち9案は写真1枚への応用候補、1案は複数素材が必要である。候補には出典・使う条件・避ける条件を付け、未確認の好みや生成品質を補完していない。

実例の現在の字体名・透明度・行間などを測定したわけではなく、1つの検索結果からの観察なので旅ジャンルや検索順位の偏りもある。日本語の明朝への応用など、実例からの転用部分は未検証。現在のモデル・プロンプト・API契約・採点・画面は変更していない。型の生成への接続と、完成画像による比較は未完である。
