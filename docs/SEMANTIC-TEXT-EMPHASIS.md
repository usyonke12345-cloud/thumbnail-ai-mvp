# 見出しの意味から強調する語句を選ぶ

2026-11-02。通常の `referenceMode: required` の生成を、写真1〜4枚とも `ai-complete-0.14.0` とする。一般的な「休日」「一日」などの語に色が付き、動画を特徴づける人物・数値・行動が目立たない問題に対する変更。

## 判断する順番

1. 現在のタイトルと動画内容から、その動画を見る理由となる特徴を考える。利用者が今回明示した強調の希望を優先する。
2. 選手・職業・実績など人物を特徴づける句、数値と単位・範囲、固有の対象、中心の行動・変化・問題を、意味に応じて比較する。数値や固有名を常に選ぶ固定ルールにはしない。
3. 中心句を決めてから色・帯・大きさ・太さを使う。単に末尾や短い語だから色を変えない。接続語や一般的な状況説明は従属させる。
4. 静かな日記や単色の希望では、色を増やさずに強弱を付けてもよい。手入力の見出しは書き換えない。修正では、依頼されていない強調の変更を避ける。

たとえば資格や職業のある人物の休日なら、その人物の特徴を「休日」より優先して検討する。記録が見どころなら数値・単位・範囲を一緒に扱う。参照の言葉や結果を別の動画へコピーせず、現在の入力にない強い事実も足さない。

## 実例に追加する観察

既存の観察 `thumbnail-reference-observation-1.0.0` に任意の `emphasis` を加える。旧台帳はそのまま読み込める。新しい `thumbnail-text-emphasis-1.0.0` は次を持つ。

- `mode`: `selective`（一部の強調）／`uniform`（主見出し全体が同じ扱い）／`no_text`（主見出しなし）／`uncertain`（未確認）。
- `spans`: selectiveだけ1〜3語句。それぞれ読めた文字（50文字以内）、意味の役割、色・大きさ・太さ・帯・輪郭の区別、見た目。
- `relationship`: 現在の入力へ転用する一般的な関係。300文字以内。

意味の役割は観察者の解釈であり、作者の意図や注視・CTRの計測結果ではない。包装のラベル・透かし・ゲーム内UIを、サムネイルの主見出しとして数えない。読めない語句は推測しない。意味を持たない文字単位の多色装飾も、中心句の色強調と混同しない。

今回、既存の100件について、キャッシュ済みの実画像と取得済みのYouTubeタイトルを照合して観察した。内訳は一部強調52、全体同じ扱い32、主見出しなし16。動画本編や字幕は視聴・解析していない。再生数は収集条件であり、色選びの正解や品質の証拠ではない。画像・出典と具体的な語句の記録は非公開で保管する。

通常生成は、100実例から雰囲気・話題・素材で選んだ最大5件の観察へ、強調の関係を加える。生成APIへは参照の実際の語句を送らず、役割と見た目・一般化した関係を渡す。画像送信の許可は増やさない。観察内容の変更は既存のobservation/pool/libraryのハッシュとA固定IDに反映される。

## 変更範囲と互換性

OpenAPI0.3.12で観察入力へ任意のemphasisを加え、required生成0.14.0の説明と応答条件を更新する。共有ファイルと台帳の契約は相互レビュー対象。1〜3枚のoff/auto生成（0.10.2/0.11.0）と4枚のoff/auto生成（0.13.0）の版は維持。旧出力の版・写真・比較結果は上書きしない。比較・診断の外側の版、Assessment、点数、重み、採点側ファイル、依存パッケージは変更しない。

追加のモデル呼び出し・学習ジョブ・動画のダウンロードはない。同じ1回の画像編集へ指示を加える。モデルの重みの再学習ではない。実際に選ばれた見出し・強調語句・文字色の自動取得や保証はしていない。

## 検証

[人工fixture](fixtures/text-emphasis.json)で形式・上限・不正な観察の拒否を確認する。ハッシュの異なる参考への保存拒否、観察だけの変更による固定IDの失効、1〜4枚で同じ1回の編集へ指示が入ること、参考語句をコピーしないこと、旧記録の読み込み、JSON/ZIP/解析への保持をテストする。実画像で期待した語句が着色されるかは、次の本人による生成確認で評価する。

手法は[OpenAIの画像プロンプトガイド](https://developers.openai.com/api/docs/guides/image-prompting)の、文字と字体・位置を具体化し、変更点と維持点を分ける方針を参考にした。この文書は今回の改善効果を保証するものではない。
