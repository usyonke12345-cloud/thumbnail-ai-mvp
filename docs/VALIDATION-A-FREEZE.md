# A検証の入力と版を固定する

検証の準備にだけ使う。入力を固定しても、生成・人の比較・素材の利用確認を実施したことにはならない。新しい有料生成は本人が毎回同意して操作する。既存の生成回数上限と自動再試行なしの設定は維持する。

## 操作

1. `/editor`で検証に使う写真・切り取り位置・動画タイトル・任意の補足と仕上がりのイメージを決める。初回の比較は見出し・デザイン・構図をautoにする。手動設定を使う場合も固定記録とChatGPT依頼文に残る。
2. 修正モードなら解除する。「A検証の入力を固定してZIP保存（無料）」を押す。無料のローカル処理で、OpenAIへは送信しない。
3. ZIPを保存できたことを確認する。固定中は評価メモをオフにし、メモ欄の操作を無効にする。リロード・既存の下書きZIPによる移行でも固定状態を維持し、送信同意は復元しない。
4. この段階では有料生成は不要。比較を実施するときに、通常の送信確認へチェックして生成する。固定IDを付けてサーバーへ送り、写真・入力・実行コード・設定が同じことを有料API呼び出し前に照合する。条件が違う場合は生成しない。
5. 条件を変える場合は別ケースとして固定し直す。旧ZIPと失敗の記録も残す。「固定を解除」しても評価メモはオフのままなので、Bを検証するときは明示的に戻す。

## ZIPに入るもの

- `source.png`：APIへ送る写真そのもの（1280×720）。元ファイルや無料編集の文字・影ではなく、切り取り後の写真。ChatGPTにもこのファイルを添付する。
- `validation-a.json`：固定ID、時刻、写真のSHA-256・バイト数、タイトル・補足・イメージ・見出し作成方針・デザイン・構図。生成版、モデル、品質、サイズ、枚数、評価メモなし・修正なし、Node版、対象ソース各ファイルと全体のSHA-256も入る。
- `service-prompt.txt`：サービスが送る画像編集の指示そのもの。SHA-256も記録する。
- `chatgpt-prompt.txt`：同じ内容・イメージ・見出し方針で直接依頼する文。ChatGPTの新しい会話へ、この文と`source.png`を渡す。手動の構図・デザインがある場合は依頼文にも含める。
- `README.txt`：比較時の注意。

入力の照合用ZIPであり、サイトへの読み込みには対応しない。編集用の元ファイルや切り取り設定を別PCへ移す場合は、既存の「下書きZIPを保存」も使う。写真と入力内容を含むので、Gitや公開PRへ入れず、非公開で扱う。

## 版と記録の意味

形式は`validation-a-case-1.0.0`。固定IDは、正規化した入力と写真のハッシュ、生成設定・実行コード・Node版、実際のサービス指示から決める。写真や文言が同じでも、コードや実行環境が変わったら別ケースになる。Gitコミット番号だけでは未コミット変更を識別できないため、起動時に読み込んだ対象コードのハッシュを記録する。起動後にディスク上だけを変更したコードへ自動で切り替わることはない。コード更新時はサーバーを再起動し、ケースを固定し直す。

初期条件は生成`ai-complete-0.6.1`、`gpt-image-2.5-flare`、`images/edits`、medium、1536×864、PNG、1枚。モデル・プロンプト・画像生成の挙動は変更していない。上流の同名モデルに更新や生成の揺らぎがあるため、同じ画像の再現を保証しない。ChatGPT内部のモデルは同一と推測せず、製品として比較する。

このZIPは固定入力の証拠であり、実際に生成した証拠ではない。`X-Validation-A-Case`付きの完成PNG成功応答だけに`validationA`照合結果を付ける。既存の比較JSON・解析dataset・採点契約は変更せず、この照合結果はそこへ自動転記しない。入力ZIPを比較用資料と一緒に保存する。完成画像・試行結果・時間・実費・人の評価は既存の記録と併せて残す。実費不明はnull、最初の出力と失敗を含める。

## 共有契約への影響

`POST /api/v1/validation-a/freeze`（JSON上限4MiB）を追加。CompleteRequestからconsent・feedback・revisionを除いた入力を受け付け、ローカルで検証・固定記録の作成だけを行う。画像プロバイダーを呼ばず、サーバー保存もしない。レスポンスの画像はハッシュ参照のみで、ブラウザが手元の写真と組み合わせる。

既存の完成PNG APIに任意の`X-Validation-A-Case`ヘッダーを追加。照合できなければ400/409、評価メモや修正元を含む場合も有料呼び出し前に拒否する。ヘッダーなしの従来入力・出力は維持する。これは再現条件の照合であり、認証や改ざん防止の署名ではない。API・OpenAPIと任意の下書きvalidationAは共同レビュー対象。採点・データ・依存関係に変更はない。
