# Day5：人の選択と仮スコアを比較する

## 現在の準備

無料デモの候補画面 `/` で3案を比較し、各案の理由欄と「この案を選んで記録」を使います。これは自動学習ではありません。最新1件をブラウザ内に保存し、JSONで書き出します。記録操作はAPI送信を行いません。

記録には動画タイトル、ジャンル、選んだ候補ID・作風、理由、表示順、全候補の採点結果と生成バージョン、所要時間を含めます。画像は含めません。完成PNGエディター `/editor` の結果は未採点で、この比較対象には含めません。

候補画像の表示を通常 / 168 / 246 / 360pxへ切り替えられます。画面が狭い場合は候補カードの幅が上限になります。選択時の実際の画像表示幅（CSS px）をactualDisplayWidthとして記録します。OS・ブラウザ・使用フォントは記録しないため、採点側の正式な縮小表示検証表の代替にはなりません。表示の切り替えは再生成せず、保存するPNG/JPEGの1280×720も変えません。

## 評価担当との接続

評価担当の `data/templates/preferences.template.csv` と、このJSONは別形式です。CSVのcandidate_idは「比較した組」のID、JSONのcandidateIdは「選んだ画像」のIDなので、そのまま対応させないでください。出典・許諾・評価者ID・全案の順位・dev/holdoutは、この画面では入力していません。これらを推測で埋めたり、許諾済み20件に数えたりしません。

相手には、全候補の採点と人の選択を比較する参考記録として渡せます。正式なデータ取り込み形式は相互確認してから決めます。現段階は最新1件の記録で、継続収集には都度JSONを書き出す必要があります。個人の記録をGitへコミットしないでください。

## 残作業

- 同じ画像を固定して比較できる非公開の画像保存・組IDの仕組み。
- 許諾・出典・評価者・順位を含む採点側の記録形式との合意。
- スマホ幅での人の比較、失敗理由の分類。
- 実費と保存成功の記録。APIレスポンスだけから請求額は推測しない。

上記の仕組みは以下の更新で実装済み。残っているのは実際の20件の記録、ブラウザでの固定保存・復元の確認、相手の運用レビュー、その実データでの分析。

## 5項目を実施する現在の手順

担当：20件の人の比較はユーザー本人（2026-10-09に確認）。Codexは固定保存・記録・書き出し・集計を実装し、評価担当の既存分析コードへ接続する。人の選択・許諾・実費は生成しない。

1. `/` で自分の実際のタイトルを入力し3案を生成する。現在の確認サーバーは無料demo。比較対象はSVGの3案で、完成PNGは対象外。
2. 「この3案を固定保存」を押す。画像、組ID、生成・採点バージョンがIndexedDBに保存される。以後同じ組IDの画像は置き換えない。
3. `/review` で同じ3案を再表示する。サンプルIDはs001から補助入力、評価者はr01。実際の出典・許諾・確認日を記入し、表示幅を変えて選択・順位・理由・失敗分類を記録する。OS・ブラウザも記録。実際の文字フォントは取得しないので、相手のreadability.csvの代替ではない。
4. 実費が未確認なら空欄。無料demoは0を初期入力する。PNG保存結果は人が確認してyes/noを記録し、未確認はunknownを維持する。
5. 違うタイトル・組で繰り返す。人工・許諾未確認は20件に数えない。人の記録は現時点ではまだ0件（UIから記録されるまで完了扱いにしない）。同じ組・評価者・実表示幅では更新保存する。

集計画面は、同じ評価範囲の候補だけを比較し、一致・同点・不一致と全案不採用を分ける。dev/holdoutを分けて集計し、文字・構図・素材・その他の失敗分類、生成時間の中央値/p95、確認済み費用・未確認件数、PNG保存のyes/no/unknownを表示する。費用と生成時間は同じ組を複数回評価しても二重加算しない。生成失敗のAPI試行を保存していないため、API成功率は算出しない。

## 相手へ渡すファイルと分析コマンド

比較画面で各組の「画像付きJSON」と、全体の「記録と集計JSON」を保存する。画像付きJSONは同じ画像を相手が再表示するための非公開ファイル。取り込みは画像セットだけで、人の評価や許諾の申告は取り込まない。

同じフォルダー `data/private/review/` に `comparison-report.json` と各 `<組ID>.json` を置く。画像付きJSONのファイル名は書き出したまま使う。実データはGit除外。コマンドは読み取りとローカル書き出しのみで、APIを呼ばない。

```sh
node scripts/analyze-comparisons.mjs data/private/review/comparison-report.json data/private/review
```

`preferences.csv`・`scores.csv`・`analysis.json` を同じフォルダーに出力する。採点側の `data/validate.mjs` と `data/agreement.mjs` を利用し、サンプルIDによるSHA-256のdev/holdout振り分けを合わせる。生成側で採点の重みを変更しない。全案不採用・人工・未確認・評価範囲違いはCSVに無理に変換せず、JSONで理由を残す。CSVだけを相手へ渡すとこれらが抜けるのでanalysis.jsonも渡す。

ブラウザでは表示幅ごとにCSVも書き出せる。画面が狭く指定幅どおりでない場合、その実表示幅はJSONには残るが指定幅CSVからは除外する。CSVを表計算ソフトで開く場合はテキストとして取り込み、利用者が入力した文字列を式として実行しない。

## 現在の完了範囲

画像固定・組ID、相手の現行CSV形式への変換と検証、比較・失敗分類・時間・費用・保存結果の集計は実装した。相手の分析コードを実際に呼ぶ経路と出力は人工テストで確認。実際の20件の評価と、そのデータに基づく分析結果はユーザーの記録待ち。相手への自動送信、採点モデルの追加学習、完成PNGの分析は行わない。server変更は静的な4ルートの追加だけで、共有APIやAssessment契約は変更しない。取り込み方針は相互レビュー対象。

表示幅168 / 246 / 360pxや48px満点は仮の値です。少数の好みをCTR予測や一般的な品質の正解として扱いません。

選んだ候補は枠とボタン表示で区別します。別の候補を選ぶと最新の記録を置き換えます。「最新の選択記録を消す」はブラウザ内の選択記録だけを削除し、書き出したJSONやエディターの写真下書きは削除しません。新しい3案を生成しても、前回の候補を選択中として表示しません。

3案とも使いたくない場合は「どの案も使わないと記録」を使い、理由を残せます。JSONのdecisionはnone_acceptable、選んだcandidateIdとassessmentはnullです。候補を選んだ記録はdecision=selectedです。これは「順位が最下位」の指定とは違い、採点側CSVのpreferred_candidateへ架空の候補を入れません。選択・不採用のどちらも最新1件のみ保存します。
