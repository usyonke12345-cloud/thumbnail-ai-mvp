# 写真エディターの保存・移行・修正（2026-10-12）

2026-10-13：比較一覧に「人物範囲を記録（無料・手動）」を追加。元写真と完成PNGの同じ主役を囲み、保存する。解析に渡すための範囲で、人物の保持を確認した結果や品質点数ではない。操作と座標の定義は[人物範囲の手順](SUBJECT-REGIONS.md)。

## 1. 共有ZIPをそのまま読み込む

`/editor`の比較一覧で「保存した写真・完成画像・比較記録のJSON・ZIPを読み込む」から、このアプリの共有ZIPを選ぶ。元のJSONへのNodeによる復元は不要。旧JSONも使える。ブラウザ内でZIPのCRC・SHA-256・画像参照・組IDを検証し、一括保存する。失敗しても現在の保存内容を保持する。

サイトのZIP STORE形式と、WindowsなどでDEFLATE圧縮した同形式のZIPに対応する。DEFLATEにはブラウザのDecompressionStreamが必要で、未対応の場合は説明を表示する。暗号化・分割ZIPは対象外。ファイルは70MiB以下、最大256エントリ、展開後192MiB以下、パスのはみ出しや画像領域の重複を拒否する。ZIP内のスクリプトはブラウザで実行しない。

## 2. 案件と履歴容量

「動画・案件で絞り込む」でタイトルまたは任意の案件名を選ぶ。組の名前は「この組の案件名を変更」から変えられる。生成前の任意の案件名も保存する。組ID・固定した写真と入力内容は変えない。同名の案件には複数の比較組を含められる。

最大60画像・1案件24画像・1比較組12画像、重複を除いたdata URLの合計192MiBを暫定上限とする。実際にはブラウザの保存容量制限で先に失敗する場合がある。IndexedDBの版2でPNGをSHA-256ごとにassetsへ1度だけ保存し、groupsとimagesは参照を持つ。旧版1の画像と記録は読み込み時の1トランザクションで移行する。削除では他の組も参照する画像を残し、参照のない資産だけを削除する。移行・保存の失敗は一括で取り消す。

書き出しは表示中の案件を対象にする。「全案件」を選べば全体が対象。70MiBを超える場合は案件や組に分ける。画像取得後の保存失敗は生成失敗と分け、表示中の画像をファイルへ保存できる。既知の枚数上限は有料生成前にも確認する。画像の実際のバイト数とブラウザの残容量は生成前には確定できない。

案件名・修正参照・7枚以上の組はcomplete-comparison-1.6.0、これらまたは拡張した件数を持つ全組reportはcomplete-comparison-report-1.1.0。旧各組1.0.0〜1.5.0、旧report1.0.0も読む。その他の旧入力は従来形式・組IDを維持する。解析datasetは案件名や修正参照があれば1.4.0。相互レビュー対象だが、Candidate/Assessmentとimage-assets-1.0.0は変更しない。

## 3. 下書きを別PCへ移す

写真入力欄の下にある「別PCへ下書きを移す」から「下書きをZIPで保存」を使う。元のPNG/JPEG/WebP写真、切り取り位置、入力欄、案件名、最後の完成画像、任意の修正元を含む。APIキーと有料送信の確認は含めない。比較履歴は共有ZIP、試行履歴は履歴JSONで別に保存する。

別PCの同じ版のサイトで「下書きZIPを読み込む」を選ぶ。写真のSHA-256と設定、画像の読み込みを確認し、下書き保存が成功したあと画面へ反映する。生成中には取り込まない。復元後の有料送信の確認は外れた状態で、生成は自動実行しない。下書き形式はphoto-editor-backup-1.0.0、ZIP70MiB以下、元写真は各20MiB以下。

## 4. 完成画像の保存形式

完成画像や比較案の「サイズ・形式を変えて保存（無料）」から、1536×864 / 1280×720 / 960×540 / 640×360と、PNG / JPEGを選べる。JPEGは品質を指定し、任意の1MiB/2MiBの容量目標に合わせて品質を段階的に下げる。指定サイズのまま目標へ収まらない場合は説明し、別サイズか形式を選ぶ。保存用の変換だけを行い、比較に使う元画像・ハッシュは変更しない。ダウンロード開始を保存成功の記録にしない。

## 5. 生成失敗の履歴

「生成の成功・失敗履歴」に、このブラウザからの各試行の時刻、動画タイトル、案件名、所要時間、画像取得と比較保存の結果を残す。成功、APIエラー、接続失敗、待機期限超過、画像取得後の比較保存失敗、処理中・終了未確認を区別する。試行の開始を保存できない場合は有料リクエストを送らない。

画像取得率は終了記録のある試行が対象で、比較保存失敗でも画像を取得できた試行は分子へ含める。期限超過後にAPI側で完成・課金したかは未確認。リロードなどで終了記録がない試行を、成功や失敗へ勝手に変更しない。APIの実費は推測せずnullにする。既存の画像別の確認済み実費は比較一覧に残る。履歴はIndexedDB thumbnail-generation-attemptsへ保存し、complete-generation-attempts-1.0.0のJSONで書き出す。画像・APIキー・送信の同意は試行履歴に保存しない。

## 6. 完成画像から修正を始める

比較案の下に修正指示を入力し、「この画像から修正を始める」を押す。元写真と固定した入力を準備し、前の完成PNGを参考として表示する。準備だけではAPIを呼ばない。「修正元の指定を外す」で通常生成へ戻せる。

手動確認のあと生成すると、元写真を人物・環境の根拠、前の完成PNGを構成・字体の参考として1回の画像編集へ送る。1回1枚・medium・起動内上限・自動再試行なしを維持する。通常生成より画像入力が増え、実費が異なる場合がある。修正元PNGと元写真の保持、文字の正しさは実画像で確認する。画質・部分保持は保証しない。今回の実装では実APIを呼ばず、再現性は未検証。

APIの任意revisionはinstruction（1〜300文字）、parentImageId、imageDataUrl（1536×864 PNG、バイナリ16MiB以下、data URLは22,369,646文字以下）。元写真は従来の1280×720 PNG。リクエスト本文上限は28MiB。生成版はai-complete-0.7.0。比較画像のrevisionは修正指示・親の内部画像ID・親PNGのSHA-256だけを持ち、親PNGを重複して埋め込まない。元案は削除しない。入力の写真やタイトルを変更した場合は別の比較組になる。

成功応答にも修正元IDとPNG本体のSHA-256を残す。比較一覧・JSON・共有ZIPのプレビューは、比較組内に元画像が無いと「修正元は未確認」と表示する。元画像がある場合はIDとハッシュを照合し、不一致の読み込みを拒否する。照合結果は人による品質評価ではない。元画像を別の組として解析に追加した場合、解析datasetは取り込んだ全画像から照合結果を再計算する。

参考：[OpenAIの画像編集API](https://developers.openai.com/api/reference/resources/images/methods/edit)、[画像編集の指示](https://developers.openai.com/api/docs/guides/image-prompting)。モデルは既存のgpt-image-2.5-flareのまま。

## 7. 手元の動画から写真を取り出す

「動画から写真を取り出す（無料）」で500MiB以内の動画を選ぶ。ブラウザで再生または秒数を指定し、「この場面を写真に使う」を押す。動画自体は外部へ送らず、選んだ場面のPNGだけを写真入力に置く。切り取り位置はそこから調整できる。動画の読み込み・シークが完了するまで取り出さない。

利用できる動画形式・コーデックはブラウザに依存する。4000万画素を超える動画は拒否し、取り出しは最大3840×2160の枠へ縦横比を保って縮小する。未対応動画や取り出し失敗では入力写真を保持する。有料生成は別の確認操作を必要とする。

## 8. 起動と復旧

Node.js 22以上とGitでプロジェクトを取得し、初回はnpm ciを実行する。npm run doctorでNode・依存・ローカル設定・ポート・既存サーバーを確認する。APIキーは値を出さず、設定済みかだけを表示する。

```sh
npm run doctor
npm run start:local
```

Windowsではstart-thumbnail.cmdをダブルクリックして起動できる。既定ポートは.envのPORT、未設定なら3004。cmdでは3004を指定する。別のポートはnode scripts/start-local.mjs --port 3005、無料で起動する場合は--free。既存の自分のサーバーは再起動せず再利用し、別のアプリがポートを使っていれば停止せず説明する。--freeで有料設定の既存サーバーを再利用することは拒否する。

新しい起動では従来どおり起動内回数がリセットされる。OPENAI_MAX_CALLSの上限・キー・有効化の設定は勝手に変更しない。doctorは生成せず、起動も自動生成しない。依存パッケージの不足はnpm ciの案内だけで、自動インストールしない。終了はCtrl+C。
