# 完成PNGを3案まとめて作る

2026-11-06。

エディターの「一度に作る枚数」で「異なる3案をまとめて作る」を選び、3枚分の有料生成への確認を入れて生成する。同じ写真1〜4枚、タイトル、補足、イメージ、見出し指定、評価メモから3枚を並行して作る。

自動設定の案Aは写真重視と左の見出し、案Bは落ち着いた誌面風と上の見出し、案Cは右の見出しと写真の対比を指定する。手動のdesign/compositionは優先する。写真の加工範囲と見出し・強調語を事前に指定した場合、その内容も3案に渡る。結果の見た目は本人が確認する。

「生成前に見出し・写真の使い方を決める（無料）」では、見出し・強調語・主役の写真・加工範囲を確認してから生成に進める。この準備を選んだ場合は、同じ内容を3案に適用する。編集中の準備案はページ内で保持する。A検証の固定入力と修正元を指定した生成には適用しない。

生成枠は開始時に3枚分をまとめて確保する。残り2枚以下では開始できない。API呼び出しは3回で、それぞれn=1・medium・1536×864。3案が終わるまでプロバイダーの生成ロックを保つ。各案の失敗・成功を返し、成功した画像は個別にダウンロードできる。失敗でもAPI料金が発生する場合がある。

返ってきた3案を画面に並べ、成功した画像は同じ比較組へ保存する。比較一覧では各画像の指定design/compositionを記録する。保存に失敗した場合は、その画像のPNG保存リンクと案ごとの状況を表示する。試行履歴は3件作り、APIエラー・接続失敗・期限超過・比較保存失敗を案ごとに記録する。実費の欄は未確認のまま残す。

ブラウザのimageElapsedMsと比較一覧の所要時間は、まとめて返る画像応答を受信するまでの時間で、成功した案に共通する。API応答内のitems[].elapsedMsはサーバーで計った各画像編集の時間。人の操作時間とは別の記録である。

A検証の固定IDを使う生成は、最初の1枚を保存する既存の手順を使う。3案の生成は通常生成で試す。

## APIと相互レビュー

OpenAPI0.3.13でPOST /api/v1/complete-thumbnail-batchを追加する。本文は既存の完成生成と同じ入力で、上限36MiB。応答はapiVersion 1、mode ai_complete_batch、items 3件。index 0〜2は案A〜Cの順。各要素はlabel、適用したsettings（design/composition）、elapsedMsと、完成PNGのresultまたはerrorを持つ。通常の1枚生成の各結果形式を共通して使う。

入力・参考ライブラリを3案とも検証してから有料呼び出しへ進む。X-Validation-A-Case付きの要求は400で停止する。残り枠の不足や別の生成処理中は429、設定や実例の不足は既存のエラーコードを返す。3回の呼び出しが始まった後の一部失敗は200のitemsに含め、成功画像を保持する。

server、プロバイダーの排他制御、OpenAPIと保存容量の事前確認は相互レビュー対象。画像ごとの生成版は、指定した入力に対応する既存の版を記録する。

人工fixtureとモックで、3回が重なって実行されること、枠の原子的な確保、他の生成の排他、一部失敗、明示設定の優先、4素材の保存、案ごとの試行記録とダウンロードリンクを確認する。
