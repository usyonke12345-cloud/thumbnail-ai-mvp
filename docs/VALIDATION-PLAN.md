# A＋Bの価値を確かめる（2026-10-15、本人合意）

主な仮説は、A「最初の1枚をそのまま使えるか」と、B「評価を重ねると本人の好みに近づくか」。品質が上がったとはまだ扱わない。比較条件をそろえた少数確認、本人の素材を使うYouTuber 3人のデモ、20回の生成記録を優先する。Cのコード文字合成は、誤字や字体が繰り返し不採用の原因になった場合に検討する。

## 担当と順番

1. 生成側：PR #7・#8のレビュー指摘を直し、入力・出力・評価メモの版を固定する。
   Aの入力固定は、エディターの「A検証の入力を固定してZIP保存（無料）」を使う。送信する写真と同条件のChatGPT依頼文、生成設定、実行コードのハッシュを残し、評価メモを使わずに照合する。詳細は[入力を固定する手順](VALIDATION-A-FREEZE.md)。固定だけでは有料生成や人の比較は行わない。
2. 共同：デモ候補3人を決め、素材のAPI送信と比較への利用を確認する。候補者の決定と連絡は本人が行う。まだ依頼・デモは未実施。
3. 生成側：同じ入力から比較画像を準備する。人が有料送信を確認して1回1枚作り、自動で20回回さない。
4. 採点側：出所・条件を伏せたページと記録表を渡し、判断を保存したあと対応表と照合する。
5. 共同：使わない理由と手間・費用を見て、改修する問題を選ぶ。この確認の前に便利機能の追加を広げない。障害やデータの不具合は直す。

## A：サービスとChatGPT直接依頼の比較

まず日本語タイトルで比較し、英語の結果とは分ける。本人の写真と実際の動画タイトルを使う。写真はサービスが送信した1280×720のPNGそのものを保存し、ChatGPTにも同じPNGを添付する。タイトル、内容の補足、希望の雰囲気、手入力の見出しの有無をそろえる。サービス側は評価メモを無効にし、AにBの効果を混ぜない。

ChatGPTは新しい会話で、PR #11の `node data/ab-compare.mjs prompt` が作る次の短い依頼文を使う。任意欄はサービスと同じ値にし、空欄ならその行を省く。サービス内部の人物・切り抜き・再配置・字体・位置の詳細ルールは足さない。手で書き写すより、新しい固定ZIPのchatgpt-prompt.txtを使う。

```text
この写真を使って、YouTube動画のサムネイル画像を作ってください。
横長（16:9）でお願いします。
動画タイトル：「［同じタイトル］」
動画の内容：［同じ補足。空欄ならこの行を省く］
仕上がりのイメージ：［同じイメージ。空欄ならこの行を省く］
動画タイトルをもとに、サムネイルに入れる短い見出しを考えて入れてください。
写真の人物はそのまま使ってください。
```

手入力なら自動見出しの行だけを `サムネイルに入れる文字：「［同じ見出し］」（この文字だけを入れてください）` に置き換える。PR #11のタイトル上限は60文字。アプリは120文字まで扱えるが、正式な比較条件を生成前に合わせ、勝手に短縮しない。旧固定ZIPの詳細指示による比較は正式Aに加えず、元の画像・依頼文・評価を参考記録として残す。海辺の組（2026-10-24）はこの参考記録で、pair02へ割り当てない。

まず双方の最初の1枚を採用し、失敗を良い画像が出るまで隠して作り直さない。生成失敗も記録する。修正を比べる場合は別の試行として、同じ修正要求・上限回数を先に決める。ChatGPTに表示されるモデル・作成日・寸法は記録し、不明な内部モデルを同じと推測しない。これは製品としての比較であり、画像モデル単独や日本語指示だけの因果効果とは扱わない。

表示幅をそろえ、A/Bなどの無意味なラベルで並べる。サービス名・生成版・点数・費用・作成順を評価前に見せない。原寸も確認できるようにする。ChatGPTの画像は外部比較用の別資産として保存し、サービスの生成記録やAPI実費として偽装しない。専用の外部資産取り込みは未実装なので、Aの比較シートは採点側と用意する。

## B：評価メモあり・なしの比較

groupId全体のUTF-8文字列をSHA-256にし、先頭バイトが77未満ならholdout、77以上ならdev。sample_idと同じ方式。先頭のcomplete-も含めてもう一度ハッシュする。分類は写真や結果を見て変更しない。

devだけを指示の調整とメモに使う。holdoutに保存した評価は、全案件を選んでもメモに使わない。新しいAPIもholdoutを含むメモを有料呼び出し前に拒否する。過去の生成に既に使われたholdoutの評価は消さず、feedbackAuditに記録する。その組は効果確認に使わず、新しい入力のholdoutを用意する。

同じholdout入力で、メモなし／ありを1枚ずつ作る。写真・タイトル・補足・イメージ・見出し方針・デザイン・構図・生成版・品質・サイズを同じにする。生成前にdevのメモを固定し、片方を見てから理由や入力を改善しない。生成順はコイントス等で先に決めて記録する。画像生成には変動があるので、1組の結果だけで効果を断定しない。メモありでも悪くなる結果・同点・両方不採用を残す。

解析は各画像にfeedbackUsedとfeedbackUsageKnown、各組にsplitを追加する。feedbackUsed:trueはメモを渡した記録があることを表し、反映成功の判定ではない。falseでもfeedbackUsageKnown:falseなら条件不明で、対照に使わない。

解析フォルダーから無料でブラインド確認用の資料を作れる。

```sh
node scripts/prepare-feedback-trials.mjs data/private/complete-analysis r01 data/private/blind-r01
```

指定を省いた旧コマンドは生成0.6.1のまま。現行の生成0.10.2で準備する場合は、対象の版を明示する。

```sh
node scripts/prepare-feedback-trials.mjs data/private/complete-analysis r01 data/private/blind-0.10.2-r01 --generation-version ai-complete-0.10.2
```

同じ生成版・構図・デザイン・参考資料条件で、修正生成ではなく、元写真と完成画像のPNGが解析可能な組だけを対象にする。参考autoでは送信記録が両方に必要で、ライブラリ・候補・観察ハッシュ・参考画像送信の有無がすべて一致する必要がある。参考offとauto、条件が不明なauto同士は対照にしない。未知の生成版や、holdout除外を入れる前の0.6.0は受け付けない。出力先は新しいフォルダーにし、既存の記入表がある場所には何も書かない。

1組に複数ある場合は、点数や人の選択で選ばず、生成時刻・ID順で最初の組み合わせを使う。0組なら比較条件がまだそろっていない。旧画像・評価・固定条件は書き換えない。明示した版は非公開の対応表へ残し、評価者向けページ・CSVには表示しない。0.6.1以外を指定した対応表はfeedback-blind-trials-1.1.0。公開API・Candidate/Assessment・採点・生成指示の変更はない。

A用に評価メモなしで作ったpair01〜05だけでは、Bのメモあり・なしの対照はそろわない。資料作成ができてもBを実施済みとせず、Aの評価後にdevのメモと新しいholdoutの条件・生成順を決める。

photo-review.htmlとphoto-review.csvは採点側の既存シートを使う。pair-choices.csvには該当する2つのp番号とA/Bだけを書き、本人がA / B / tie / neitherと理由を記入する。条件の対応はprivate-answer-key.jsonに置き、判断を保存するまで見せない。評価者にはそのファイルを渡さない。生成を操作した本人は見た目を覚えているため、本人だけの比較は探索的な参考結果とする。

## YouTuber 3人に聞くこと

- このまま自分の動画に使うか。
- どこを直したいか。
- お金を払って使いたいか。その理由と、今の作り方で困っている点。

匿名IDで記録し、素材の利用確認、確認日、作成に立ち会ったかを残す。支払意思は発言の記録であり、売上ではない。会ったことのない架空の利用者や感想を作らない。まず3人中2人が少なくとも1枚を使いたいと答える、という従来の暫定目標で確認する。少人数で市場全体の需要を断定しない。

## 20回の生成で記録するもの

アプリの生成試行履歴を使い、開始・成功・APIエラー・接続エラー・タイムアウト・保存失敗・未確定を残す。所要時間、最初の使用可能な画像に至るまでの試行回数、PNG保存確認も記録する。成功率は結果が判明した試行の母数と未確定数を併記する。既存の成功画像だけを母数にしない。

実費は請求・利用履歴で確認したものだけを記入し、不明はnull。失敗・期限超過でも実費が不明なら0にしない。ChatGPT直接依頼の費用とAPIの実費を同じ請求として足さない。評価メモの効果、利用確認済み20タイトルの収集、20回の動作確認は別の進捗。

完成PNGの評価は、写真の描き直し、文字の誤り・雰囲気、困る写り込み等の失敗を見つけるために使う。現状の輝度・彩度だけで画像を品質順に並べたり、CTRを予測したりしない。既存SVGの仮採点は別経路で、主方式の価値として宣伝しない。
