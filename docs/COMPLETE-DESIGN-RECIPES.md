# 完成PNGの構成をAIに任せる

生成版ai-complete-0.4.1。希望する雰囲気をvisualIntentで伝え、構成・字体はAIに任せられる。9つの組み合わせ候補は実験段階の出発点であり、使える品質の確認は実画像で行う。追加した自然な手書き風と余白の組み合わせは、本人による1枚の使用可の確認を参考にした。別入力での再現性は未検証。[パターンを増やす手順](STYLE-PATTERN-GROWTH.md)。design=autoはそのまま画像モデルへ渡し、画像編集と同じ呼び出しで写真と動画内容を見て構成を決める。これまでの保存履歴から3方向を順番に切り替える処理は除いた。定義はshared/complete-designs.mjsで、手動の字体・配置の見本も保持する。

自動では、写真の主役・顔・手・重要な物と、文字を置ける低密度の余白を確認するよう指示する。左・右・上・下の候補から、主役を隠さず読みやすい領域を選び、動画の雰囲気と見出しの長さに合わせて字体・大きさ・改行・揃え方を決める。3つの手動レシピに限定せず、広いぼかし影や大きな空白パネルを避ける。同じ写真と内容では似た構成になることもあり、毎回違う案や最適な判断を保証しない。

画面の「AIに構成を任せる」はdesignとcompositionを両方autoに戻し、下書きだけを保存する。以前の固定指定を復元している場合もこのボタンで戻せる。見出しも任せる場合はheadlineMode=autoを選ぶ。生成ボタンを押すまでAPI送信・課金はない。

| design | 字体の指定 | composition=autoの見出し領域 |
|---|---|---|
| auto | 写真と動画内容からAIが判断 | 主役と余白に合わせてAIが判断。具体的な字体・座標は未取得 |
| photo_focus | 直立した中程度の太さのサンセリフ／ゴシック | 写真全面、下部4分の1以内の短い左揃え見出し |
| editorial | 直立したセリフ／明朝。読みやすい太さと穏やかな誌面の雰囲気 | 上部4分の1以内の見出し、残りを大きな写真にする |
| impact | 直立した細長い太字サンセリフ／ゴシック | 主役と反対側の横の空間、幅約40%以内の大きな見出し |

これはAIへの指定で、画像に使われた実フォントや文字の座標を計測した情報ではない。画面の字体見本も端末のフォントで描くため、API出力と同一とは扱わない。

左・右・上の構図を明示すると、その領域を優先する。手動のdesignでは見出しの既定領域を置き換えて字体を維持し、design=autoでは字体と文字の大きさをAIに任せる。指定した配置と既定配置をプロンプトに混ぜない。字体も配置も判断させる場合はdesign=autoかつcomposition=autoを使う。

人物を切り抜いて移動する許可を除き、顔・肌の質感と色・表情・姿勢・環境・被写体間の位置関係を保持するよう指示する。全写真の切り取りと拡縮は許す。これは保持の保証や実測評価ではなく、完成PNGで確認する。

## 接続と検証

POST /api/v1/complete-thumbnailに任意のvisualIntentを追加する。既存のenum・既定値・レスポンスの形は維持する。生成版と人工fixtureの版を更新し、OpenAPIのdesignの説明を具体化した。Candidate/Assessmentと完成PNGの未採点扱い、画像資産1.0.0は維持する。イメージを含む書き出しは1.4.0で、旧形式も読む。古い画像の生成版や希望したdesignは上書きしない。

serverには今回追加の変更はなく、0.2.1で追加した/editor-design-guide.jsと/shared/complete-designs.mjsの静的配信を使う。sharedの説明とautoの挙動は相互レビュー対象。モデルgpt-image-2.5-flare、medium、1536×864、1回1枚、手動同意、自動再試行なし、起動中の上限は維持する。追加の画像分析APIや判断理由の取得は行わない。テストは偽のAPIを使い、実際の画像生成や料金は発生しない。

保存するdesign=autoは「AIに任せた」という希望で、AIが実際に選んだフォントや位置の測定値ではない。旧画像の具体的なdesign・生成版も維持する。完成PNGは未採点で、写真保持・文字の実コントラスト・構成の妥当性は画像を見て確かめる。

見本を選ぶだけでは生成せず、デザインの選択と下書き保存だけを行う。下書き復元・削除後は選択状態と説明を更新する。実PNGの品質は別に確認する。

## 少数で確認する手順

1. 前回と同じ写真・タイトル・内容・手入力の見出しを使う。自動文言のテストは、字体と構図の確認の後に分ける。
2. 「AIに構成を任せる」でdesign/compositionを両方autoにし、有料生成に同意して1枚だけ手動生成する。見出しも任せる場合はその選択を記録し、字体だけの比較とは分ける。
3. 字体、文字位置、人物と背景の保持、小さい表示での読みやすさを確認し、完成PNG・生成版と人の理由を保存する。
4. 字体や構図が指定に従わない場合、同じ指示で20件を増やさない。文字を別に合成する方式や、構図のガイド画像を参照する方式を次の候補として検討する。

検証は、自動判断の指示、手動指定の優先順位、APIに送る写真バイトとauto指定の一致、1回だけの編集と上限、無料選択と保存状態、JSONの書き出し・取り込みと診断で指定を維持する範囲まで。0.4.0のイメージ指定と組み合わせ候補の実画像での確認は未完。2026-10-11の添付画像ではセリフ体と上部配置を目視確認したが、JSONがないため画像ID・生成版との正式な紐付けはしていない。本人の好みの評価や20件の比較は作らない。

設計の参考は[OpenAI Docsの画像プロンプトガイド](https://developers.openai.com/api/docs/guides/image-prompting)。字体と配置を具体化し、変更する部分と保持する部分を分ける。フォントファイルによる文字合成やOCRはこの変更に含めていない。
