# 完成PNGの字体と配置を分ける

生成版ai-complete-0.2.1。色が変わるだけで字体と構図が変わらないという報告を受け、デザインごとに字体と見出しの領域を具体化した。定義はshared/complete-designs.mjsで、生成側のプロンプトと無料の画面の見本が同じ定義を使う。

| design | 字体の指定 | composition=autoの見出し領域 |
|---|---|---|
| photo_focus | 直立した中程度の太さのサンセリフ／ゴシック | 写真全面、下部4分の1以内の短い左揃え見出し |
| editorial | 直立したセリフ／明朝。読みやすい太さと穏やかな誌面の雰囲気 | 上部4分の1以内の見出し、残りを大きな写真にする |
| impact | 直立した細長い太字サンセリフ／ゴシック | 主役と反対側の横の空間、幅約40%以内の大きな見出し |

これはAIへの指定で、画像に使われた実フォントや文字の座標を計測した情報ではない。画面の字体見本も端末のフォントで描くため、API出力と同一とは扱わない。

左・右・上の構図を明示すると、見出しの既定領域を置き換える。字体は維持する。指定した配置と既定配置の両方をプロンプトに混ぜない。配置も比較する場合はcomposition=autoを使う。同じdesignを固定すると同じレシピを繰り返し、おまかせでは保存済み成功履歴から次のdesignへ進む。

人物を切り抜いて移動する許可を除き、顔・肌の質感と色・表情・姿勢・環境・被写体間の位置関係を保持するよう指示する。全写真の切り取りと拡縮は許す。これは保持の保証や実測評価ではなく、完成PNGで確認する。

## 接続と検証

POST /api/v1/complete-thumbnailの入力キー、enum、既定値、レスポンスの形は変えない。生成版と人工fixtureの版を更新し、OpenAPIのdesignの説明を具体化した。Candidate/Assessmentと完成PNGの未採点扱い、書き出し1.3.0、画像資産1.0.0は変えない。古い画像の生成版や希望したdesignは上書きしない。

serverの変更は/editor-design-guide.jsと/shared/complete-designs.mjsを静的な許可リストに追加するだけで、新しい生成・保存APIはない。sharedとserverは相互レビュー対象。モデルgpt-image-2.5-flare、medium、1536×864、1回1枚、手動同意、自動再試行なし、起動中の上限は維持する。テストは偽のAPIを使い、実際の画像生成や料金は発生しない。

見本を選ぶだけでは生成せず、デザインの選択と下書き保存だけを行う。下書き復元・削除後は選択状態と説明を更新する。実PNGの品質は別に確認する。

## 少数で確認する手順

1. 前回と同じ写真・タイトル・内容・手入力の見出しを使う。自動文言のテストは、字体と構図の確認の後に分ける。
2. まずeditorialを選び、構図はauto。セリフ／明朝と上部の見出しを希望する1枚を手動生成する。
3. 字体、文字位置、人物と背景の保持、小さい表示での読みやすさを確認し、完成PNG・生成版と人の理由を保存する。
4. 字体や構図が指定に従わない場合、同じ指示で20件を増やさない。文字を別に合成する方式や、構図のガイド画像を参照する方式を次の候補として検討する。

検証は、レシピの区別、配置の優先順位、APIに送る写真バイトと指定の一致、1回だけの編集、無料選択と保存状態、新しい静的ファイルの配信まで。0.2.1の実画像での検証は未完で、プロンプト変更だけで結果が異なることは保証できない。

設計の参考は[OpenAI Docsの画像プロンプトガイド](https://developers.openai.com/api/docs/guides/image-prompting)。字体と配置を具体化し、変更する部分と保持する部分を分ける。フォントファイルによる文字合成やOCRはこの変更に含めていない。
