## 現在できること（2026-10-10）

写真からAPI生成した完成PNGと、実際に送った写真・タイトル・内容・見出し作成方針・構図とデザインの希望を固定して保存する。画像と組のSHA-256を読み込み時に再確認し、PNG診断と人の記録を採点担当へ渡せる非公開フォルダーにまとめる。PR #6の076bc4dを統合したPNG解析を使用する。自動見出しの実際の文言は未取得として扱い、手入力の見出しと区別する。

自動で確認するのは、PNGの解析可否、宣言と実際の寸法、相対輝度の間引き統計、ほぼ単色という兆候。これは品質点数ではない。文字の正しさ・小さい表示での読みやすさ・人物や素材の保持・構図の品質は未評価。文字なし背景は存在しないため、入力写真をその代用品としてコントラスト採点しない。Candidate/Assessmentには渡さず、assessmentとqualityScoreはnullを維持する。

## まず少数の入力で確認する

1. `/editor`の既存完成画像で「このPNGを無料で診断」を押す。診断はローカルサーバーへの送信だけで、外部APIを呼ばない。
2. 利用できる別の写真と実際の動画タイトルで、まず2〜3組を確認する。同じ入力写真・タイトル・内容・見出し作成方針を保ち、構図やデザインの希望を変えた2枚以上を1組として比べる。手入力なら見出しも固定する。自動の場合は実際の文言が変わるため、完成サムネ全体を比較する。写真や入力テキストが変わったら別の組にする。
3. 人物・素材、見出しの正しさ、小さい表示での読みやすさ、実際に使いたいかを本人が確認する。使いたい案がなければ「全部使わない」と理由・失敗分類を記録し、改善してから20件へ進む。
4. 評価者はr01のような匿名IDを使う。タイトルの出典と、タイトル・写真を比較分析に使えることの確認は本人が入力する。未確認を自動で確認済みにしない。自分の未公開動画のタイトルなら「自分の動画用に作ったタイトル」を選べる。URLは必須ではない。
5. 各画像の実費とファイル保存を確認できた分だけ記録する。費用不明は空欄。保存ボタンを押しただけで成功として記録しない。

有料生成は手動で行い、起動内の上限と同意確認を維持する。診断・比較画面・集計は上限を増やしたり自動再生成したりしない。少数の動作テストと、別入力でも使えるという品質の確認は別。人工テスト画像を実際の品質検証件数に数えない。

## 採点担当へ渡す

共有先でJSONの容量が大きすぎる場合は、`/editor`の「共有用ZIPを保存」を使う。同じPNGを1枚にまとめ、写真と人の記録を画質を変えずに渡す。相手はZIPをすべて展開して`preview.html`を開ける。ZIP作成ではPNGの明るさ診断は行わない。正式な診断・横断集計をする場合は、展開したフォルダーで`node restore-report.mjs`を実行し、検証済みの`complete-comparison-report.restored.json`を以下のCLIへ渡す。転送用の`report-with-asset-references.json`は直接分析しない。通常JSONの書き出しも維持する。

「全組の画像・記録・集計JSONを保存」を使う。各組のJSONだけでもよい。PNGと写真を含むため非公開で扱い、Gitには入れない。補足なしの組はcomplete-comparison-1.5.0、分析JSONはcomplete-evaluation-dataset-1.3.0。補足ありでイメージを持つ組は1.4.0、分析datasetは1.2.0、それ以外の自動見出し・デザイン指定は1.3.0。旧1.0.0〜1.4.0も読み込み可能で、欠けている実費・評価者・利用確認を補わない。補足なしはbrief:""で固定する。

受け取ったJSONをdata/private/complete-review/へ置き、プロジェクトのルートで実行する。Windowsでも同じコマンドを使える。

```sh
node scripts/analyze-complete-comparisons.mjs data/private/complete-review/batch-01.json data/private/complete-review/batch-02.json
```

出力先を変える場合は、`--out data/private/complete-analysis-02`を引数に足す。既定のdata/private/complete-analysis/へ次を出力する。

- assets/: SHA-256の名前で固定した入力写真と完成PNG。同じPNGのバイトは1ファイルにまとめる。
- preview.html: 元写真・完成PNG・保存された人のコメントを並べる確認ページ。フォルダー全体を展開してから通常ブラウザで開く。表示幅を切り替えても比較記録は追加せず、外部通信や有料API呼び出しは行わない。
- analysis.json: 画像参照、診断、固定した入力条件、生成版、人の記録、実費・時間・保存結果と進み具合。
- human-reviews.jsonl: 選択・不採用と理由。古い/不完全な記録も含むため、正式な件数にはanalysis.jsonのprogressを使う。
- README.txt: 受け渡し時の説明。

このフォルダー全体を採点担当へ非公開で渡す。CLIは外部APIを呼ばず、画像を読み込んでローカルへ書き出す。画像の破損・未対応形式は理由付きの未評価。JSONの改変で入力条件やhashが一致しない場合は処理を失敗させる。複数ファイルで同じ画像IDの内容が異なる場合も失敗する。同時刻で内容が異なる人の記録を勝手に選ばない。後日の書き出しを合わせる場合は、画像を重複計上せず新しい記録を使う。

送信後は、採点担当が入力条件・画像の対応・未評価の表現を確認する。生成担当は次の写真・タイトルによる少数確認を進める。1枚だけの品質確認を20件の比較へ繰り上げない。送付した記録の指摘と、別入力での品質を確かめてから本格的な比較を再開する。

analysis.jsonは、補足なしの組があればcomplete-evaluation-dataset-1.3.0、イメージの入力があれば1.2.0、それ以外の新しい見出し作成方針・デザイン指定があれば1.1.0、なければ従来の1.0.0。画像資産の診断契約はimage-assets-1.0.0のまま。自動見出しではheadlineProvided:null、renderedTextVerified:false、textRegions:nullを維持し、文字起こしや品質採点ができたとは扱わない。preview.htmlでも「AIに任せる（実際の文言は未取得）」と希望した方向を表示する。

## 20件を集める条件

本人が20件を比較する。1組は同じ入力から実際に作った2枚以上で、全部の案を見た記録が必要。「全部使わない」も比較結果である。1枚だけの品質確認、評価者不明、入力条件不明、破損PNG、案追加後の古い選択は20件に数えない。同じ組の記録し直しを新しい比較として数えない。

ブラウザは最大60画像を保存するため、数組ごとにJSONを保存してから不要な組を削除する。保存済みのJSONを全てCLIへ渡すと、ブラウザから削除した組も横断集計できる。progress.completedHumanComparisonsは比較記録のある組数、authorizedRealComparisonsは実タイトル（original/external）で写真とタイトルの利用確認を申告した組数。人工タイトルや未確認の記録を後者へ混ぜない。目標は20件だが、到達だけをもって品質を保証しない。

同じ組の全案の順位は現形式では記録せず、使いたい案または全案不採用を記録する。人の選択と自動品質点数の順位一致はscoringAgreement:null。自動品質評価を採点担当が実装・検証するまでは、既存SVGの点数や明るさの値で代用しない。

## APIと共同レビュー

POST /api/v1/complete-diagnosticsは追加のローカル診断API。OpenAPIのCompleteDiagnosticRequest/Responseと人工fixtureを同じ変更に含める。最大4資産、1PNG16MiB・合計32MiB、JSON45MiB、各辺4096pxまで。SHA-256で同一PNGの展開結果を共有し、RGBAは処理ごとに解放する。統計は約20万点以下へ間引く。sRGBを仮定し、色プロファイル変換はしない。一部の透明色や未対応形式は未評価にする。

共有OpenAPIとserverの追加、画像資産契約、受け渡し形式は採点担当のレビュー対象。Draft PRのまま確認し、正式な合意と実データの結果を待ってmainへのマージを判断する。本人の写真・記録を自動送信しない。
