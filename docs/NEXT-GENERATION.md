# 次の生成より前に終える準備（2026-10-25）

## 開発側の作業

1. 写真の保持：生成0.10.2で、人物追加の制限に加え、元写真にない背景・物・料理を増やさない指示を全デザインと修正へ適用。再構成でも、食べ物や商品の見える形・角度・材料・包装を保ち、二次元の切り取り・拡縮・移動と、別角度からの描き直しを区別する。色と明るさは控えめに整え、別の天候・時刻・場所に変えない。
2. 自動見出し：主題に不可欠な店名・目的地・商品名などを一般名詞へ落とさず、重要な数値は単位・範囲と一緒に保つ指示を追加。全固有名詞やチャンネル名を詰め込む指示ではない。手入力の文言は従来どおりそのまま描く。
3. 生成記録：既存APIのvalidationA照合記録を比較画像・下書き・ZIP・解析へ保持。入力の写真・文言・デザイン・構図と照合記録のハッシュが食い違えば保存・読込で拒否する。固定中の応答に照合結果がない場合も、正常に結び付いた記録として保存しない。受信済みPNGは表示して、比較保存エラーとしてファイル保存を案内する。
4. 時間と画像の対応：画像受信までの時間、試行全体の時間、返されたPNGのSHA-256、生成版を試行履歴に残す。比較保存が失敗しても、APIで画像を取得したことと保存失敗を区別する。実費は確認できなければnull。
5. 互換性と無料検証：旧比較JSON・下書き・ZIPと生成回数制限を維持。人工PNGを使い、通常・再構成・修正・API失敗・保存失敗・旧記録の読込を試す。稼働中のコードと新しい固定ZIPも無料で照合し、画像APIを呼ばずに確認する。

指示の参考は[OpenAIの画像編集ガイド](https://developers.openai.com/api/docs/guides/image-prompting)。変更する範囲と保持する範囲、入力画像の役割を明確にする考え方を使う。指示の送信を確認できても、モデルが実画像で守ったことや品質向上はまだ確認したことにならない。

## 記録形式と意味

validationAは既存のAPI応答で、固定した条件との照合記録。品質点数や写真保持の測定ではなく、独立した署名付き証明でもない。画像の組IDや既存の採点値は変えない。

照合記録を持つ比較はcomplete-comparison-1.10.0、解析はcomplete-evaluation-dataset-1.9.0を使う。既存の記録に照合結果を推測して足さない。照合記録がない旧画像は従来の版で読み書きする。試行履歴は新しい時間・画像情報があるとcomplete-generation-attempts-1.1.0、旧情報だけなら1.0.0。完成APIの形とOpenAPI 0.3.8は維持する。

各時間は次の範囲を表す。

| 項目 | 計測範囲 | 記録先 |
|---|---|---|
| 画像受信まで | ブラウザが生成要求を開始して、応答JSONを読み終わるまで。通信・受信も含む | 比較画像elapsedMs、試行imageElapsedMs |
| 試行全体 | 同じ開始点から、表示と比較保存の成否が確定するまで | 試行elapsedMs |
| 人が操作した工程全体 | 人が写真を読み込むところから、PNGのファイル保存を確認するまで。生成の待ち時間も含む | 別の作業記録。未計測はnull |

人の工程時間から推測で画像生成時間を引いたり、Codexの操作時間を人の操作時間として記録しない。ファイルの保存リンクを押しただけでは保存成功にしない。API内部だけの処理時間・トークン数・請求額は、これらの時間から算出できない。

0.10.1以前の比較画像elapsedMsには、受信後の表示処理の一部が含まれる場合がある。旧記録の時間は変更せず、速度を比べるときは版と計測範囲をそろえる。
