# A：最初の1枚の使いやすさ（このサービス と ChatGPT 直接 の比較）

目的：同じ写真・同じタイトルから作った**最初の1枚**を、どちらで作ったか分からない状態で比べ、「そのまま使えるか」「何を直したいか」「どちらを使うか」を確かめる。あわせて作成時間と、使える状態までの修正回数を記録する（Issue #9 の仮説A）。好みと使いやすさの比較で、CTRや品質の保証ではない。改善しなかった結果も含めてすべて残す。

## 流れ（順番が大事）
1. **組を決める**（作る前）→ 2. **最初の1枚を両方で作る**（時間を記録）→ 3. **出所を伏せて評価**（評価者）→ 4. **修正して使える状態にする**（作成者、修正回数を記録）→ 5. **集計**

評価（3）は修正（4）より前に行う。修正の途中でどちらがどちらか分かってしまうため。

## 1. 組を決める
- 5組以上。写真とタイトルは作る前にリストで決めて書いておく（結果を見てから選ばない）。
- 写真は本人が撮ったもの、写っている人の同意が取れているものだけ。タイトルは自分の動画のもの。
- 種類を混ぜる：人物の自撮り／人物＋背景が主役／屋内・屋外、タイトルの長さ、日本語・英語。

## 2. 最初の1枚を作る（どちらも1回目を使う・同じ条件で）
**両方に同じ条件を入れる。** 条件は組ごとの `meta.json` に先に書き、このサービスにも ChatGPT にも同じ値を使う。
- `title`：動画タイトル（必須）
- `brief`：動画の内容（任意。入れるなら両方に）
- `visualIntent`：仕上がりのイメージ（任意。入れるなら両方に）
- `headlineMode`：`auto`（画像に入れる見出しはAIに任せる）か `manual`（`headline` の文字を入れる）。**必須**。manual のときは `headline` も書く。

作り方：
- **このサービス**：`/editor` で写真と、上の条件と同じ値（タイトル・内容・イメージ・見出しの方法と見出し）を入れる。構図・デザインはAIに任せる。**評価メモは使わない**。1回生成してPNGを保存。
- **ChatGPT**：次のコマンドで、同じ条件から指示文を作る。新しい会話で写真を添付し、表示された文をそのまま送る。1回目の画像を保存。
  ```
  node data/ab-compare.mjs prompt data/private/ab/pair01
  ```
  例（`headlineMode: "auto"`、内容とイメージあり）：
  ```
  この写真を使って、YouTube動画のサムネイル画像を作ってください。
  横長（16:9）でお願いします。
  動画タイトル：「{title}」
  動画の内容：{brief}
  仕上がりのイメージ：{visualIntent}
  動画タイトルをもとに、サムネイルに入れる短い見出しを考えて入れてください。
  写真の人物はそのまま使ってください。
  ```
  `headlineMode: "manual"` なら見出しの行が「サムネイルに入れる文字：「{headline}」（この文字だけを入れてください）」になる。
- **作成時間**（`firstSeconds`）：操作を始めてから1枚目の画像が手元に保存できるまでの秒数（入力の時間も含む。おおよそでよい）。0以上の数。

## 3. 出所を伏せて評価する
```
node data/ab-compare.mjs sheet data/private/ab r01
```
- 同じ評価者のシートが既にあると、**上書きせずに止まる**（記入済みの回答を守るため）。作り直すときは、中身を確認してから手で移動・削除する。
- `ab-review-r01.html`（比較ページ）と `ab-review-r01.csv`（記入用）を評価者に渡す。**`ab-key-r01.json`（案X/案Yの対応表）は渡さない。**
- ページには「案X」「案Y」とだけ出る。どちらがこのサービスかは評価者ごと・組ごとに入れ替わる。
- 1枚ごとの項目（写真評価シートと同じ考え方。`x_` が案X、`y_` が案Y）：
  - `would_use`：手直しなしでそのまま使うか（yes / no）
  - `fix`：直したい点（`text` 文字 / `photo` 写真・人物の描き直し / `composition` 構図 / `unwanted` 困る写り込み / `color` 色 / `other`）を `|` でつなぐ。無ければ `none`
  - `fix_note`：直したい点を一言（任意）
  - `photo_preserved`：元の写真の人物・場面が保たれているか（yes / partly / no）
  - `text_mood_fit`：文字の雰囲気が内容に合うか（1〜5）
- 最後に `preferred`（X / Y / `same` どちらも同じくらい使える / `neither` どちらも使わない）と `reason`。
- 評価者は本人に加えて、できれば開発に関わっていない人を1〜2人（r02, r03 …）。

## 4. 修正して使える状態にする（評価のあと・作成者）
- 最初の1枚がそのまま使えない場合、それぞれの方法で修正する（このサービスは修正指示、ChatGPTは同じ会話で追加の依頼）。**最大3回**。
- `revisionsToUsable`：使える状態になるまでの修正回数。0〜3の整数（そのまま使えたら `0`）、3回で使えなければ `"gave_up"`、試していなければ書かない。範囲外の値は集計から外して `metaInvalid` に出す。

## 5. ファイルの置き方（非公開・Gitに入れない）
```
data/private/ab/
  pair01/ source.png   service.png   chatgpt.png   meta.json
```
- 組ID（フォルダ名）は英数字・`-`・`_`。画像は png / jpg / webp（service・chatgpt は**最初の1枚**）。
- meta.json の例：
  ```json
  {
    "title": "動画タイトル", "brief": "内容（任意）", "visualIntent": "イメージ（任意）",
    "headlineMode": "auto", "date": "2026-10-16",
    "service": { "version": "ai-complete-0.6.0", "firstSeconds": 75, "revisionsToUsable": 1 },
    "chatgpt": { "model": "画面の表示", "firstSeconds": 60, "revisionsToUsable": "gave_up" }
  }
  ```

## 6. 集計
```
node data/ab-compare.mjs summarize data/private/ab ab-review-r01.csv ab-review-r02.csv
```
- `preferred`：全票の件数（このサービス／ChatGPT／`same`／`neither`）。**複数人の票は同じ組を見ているので独立ではなく、全票をまとめたp値は出さない。**
- `byReviewer`：評価者ごとの件数と両側二項検定 `signTestP`（その人の中では組が独立。`same`・`neither` を除く。5組で5対0なら0.0625、4対1なら0.375）。少数なので「偶然でも起こりうるか」の目安。
- `pairLevel`：組ごとの多数決（1組1票。このサービス／ChatGPT／決まらない）。どの集計単位で判断するかは、結果を見る前に決めておく。
- `byMethod.service` / `byMethod.chatgpt`：
  - `wouldUseRate`：そのまま使うと答えた割合（**最初の1枚の使いやすさの中心の指標**）
  - `fixCounts`：直したい点の種類ごとの件数（採点側の「問題を見つける役割」で、どの問題を優先して検出すべきかの材料）
  - `photoPreserved`・`textMoodFitMean`
  - `creator`：作成時間の中央値、使える状態までの修正回数（記録数・中央値・あきらめた件数）
- `reasons`：選んだ理由と、方法ごとの直したい点の一言。
- 記入漏れ・不正な値の行、**同じ評価者・同じ組の2回目以降の回答**は数えず、行番号と理由を `invalid` に出す。
- 作成者の記録（時間・修正回数）の不正な値は数えず、組IDと理由を `metaInvalid` に出す。

## 結果の読み方
- **このサービスの `wouldUseRate` が高い・多く選ばれる**：理由と `fixCounts` の差が差別化の中身になる。
- **`neither`（どちらも使わない）が多い**：どちらの方法でも最初の1枚では足りない。`fixCounts` で何が足りないかを見る。
- **差がない**：価値は「比べる・記録する・好みに近づける」（仮説B）や「文字の正確さ」（仮説C）に絞る。
- **ChatGPTの方がよい**：方針を考え直す材料。早く分かるほどよい。
- 人数・組数が少ないうちは参考値。判断は数字と理由の中身をあわせて行う。
